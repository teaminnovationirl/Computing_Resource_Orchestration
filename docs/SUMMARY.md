## Gotchas and open items

- For E4-3 and X-1 (D-122): `e2.cancel_queued(job_id, by)` returns True once cancelled; raises IllegalTransition ("being admitted ... try again") for a job that reads admitted: answer 409 and let the user retry, never 202; returns False for any other state: then try e1.cancel. After a raise of any other kind, a job that now reads cancelled was cancelled (a lost acknowledgement). queue_view() gives QueueEntry only: position is the index + 1, the wait clock.time() - submitted_at (D-126). The admission state (paused, reason, policy, in_doubt) reaches pages only through admission events (D-123): no port reads it, so an admin status endpoint needs an E2Port getter (a proposal for the owner).
- For E4-3: build `SubmitRequest` with `source_name` from the multipart file name; parse form integers strictly, pass None for an absent or empty field, and turn a parse failure into 400 {field, error}, never FastAPI's 422; map ApiError to its status and anything else to a generic 500 that never echoes the exception text. Uploads are spooled (D-90, D-128): stream each upload directly into `DATA_DIR/spool` under a server-made name (never the user's file name, D-76), reading at most the type's cap plus one byte and never holding it whole in memory; close the file (on Windows os.replace fails on an open one), pass submit() its Path, and delete a spool file still there after submit() returns or raises. A ValueError from submit() is a caller bug. Pass stdin as bytes or None (only code_run takes one); its 1 MiB cap is E2's STDIN_MAX_BYTES: move it to Config when E4-3 reads it, since no engine may import E2's validation.
- For E1-1: `payload_path` is `payloads/<hex>` under DATA_DIR (folder 0755, files 0644) and holds exactly one of prog.c, prog.cpp, Main.java, prog.py or payload.zip, byte for byte as uploaded; a code_run payload also holds input.txt, the program's stdin (empty when none was given). E2 checked the zip on its declared sizes only: hold PYTHON_ML_UNZIPPED_MAX_BYTES and PYTHON_ML_MAX_ENTRIES on the bytes written and refuse absolute, '..' and link entries again while extracting, judged on the name zipfile extracts to (`filename`: the Unicode Path name when present, cut at a NUL); local headers may name entries differently from the directory, and a backslash separates folders only on Windows.
- For E1-1: compile Main.java with javac; if no class Main can be run, the verdict is a compile error with the message "Java submissions must declare class Main". E1-1 owns the Java class tests (`public final class Main`, a tab between the words, no Main); E2 checks .java only for extension and size (D-79).
- For E4-7: the startup reconciliation (startup only: a submit in progress owns a folder that no job names yet) deletes `DATA_DIR/payloads/<hex>` folders that no job names (a crash between the payload write and COMMIT, or a folder kept after submit_commit_unknown whose job did not commit).
- For X-3: lab sessions are tied to no students and no problems (D-86), so anyone naming an open exam session gets need class 1; a fix needs a schema change.
- For E1-2, E4-6 and E4-7: release() accepts completed, failed and cancelled; for allocated or running it raises IllegalTransition (make the terminal move only after the confirmed stop, then release), for an unknown id NotFound. AlreadyReleased says only that nothing was open (the release line's state tells a repeat, released, from a job that held nothing); recover() still calls requeue(), which checks released itself (plan 8.4): False means the retries are used up (the job stays released; its history shows how it ended); NotFound or IllegalTransition means nothing was written; any other error is logged as outcome failed (rolled back: the job is still released, call requeue() again) or commit_unknown (if it committed, the resync pushes it within 30 s and a second call raises IllegalTransition "queued") (D-121). A release() that raises (pool timeout, retries used up, a lost COMMIT acknowledgement) may leave the allocation held: log it with the job_id and call release() again; only the owner of the attempt's end (D-08) calls it.
- For E1-2, E4-6 and X-1: pass `expected=` to transition() whenever the decision was based on a state read earlier (D-65). Without it, a cancel decided while the job was allocated applies as running to cancelled once E1 has started it.
- For every engine: inside tx(), take savepoints only with `with cur.savepoint():` (CLAUDE.md, D-67), never connection.transaction(); a caught database error without a savepoint makes tx() raise at exit (D-48).
- For E1-2: transition() locks the job row; call it after any allocation and resource locks, never before, or concurrent callers deadlock (40P01, retried 3 times by retrying()). allocate() and release() do so; the lock probes in `tests/e3/test_e3_allocation.py` and `test_release.py` show how to test it.
- For E4-7 and any bulk move: one transaction per job. Each transition() takes a savepoint, and more than 64 in one transaction overflow PostgreSQL's subtransaction cache, which slows every snapshot.
- For E4-4: a job_state event can be lost (a failed push or a crash after COMMIT, D-47) or arrive out of order (hooks of different transactions run on different threads). Pages refetch on (re)connect and ignore an event whose `at` is older than the last one seen for that job. Values passed in `extra` must be JSON-serialisable. E2 publishes job_state and admission events while it holds its lock (D-104, D-123): the hub must never call E2 while holding a lock of its own, or the two can deadlock.
- Tests that count hub events or E1 calls take a baseline after make_job: each make_job step publishes one job_state event, and the allocate step of an allocated or running job also records one dispatch and one capacity event. make_job allocates on S0 for real: 28 jobs of the default vector use up the CPU, so loops pass a small vector (Vector(100, 64)). make_job("completed"), ("failed") and ("cancelled") hold no allocation (D-73); a job that must end holding one starts from make_job("running") and moves on, as finished() in `tests/e3/test_release.py` does.
- For E1-2: dispatch runs right after allocate()'s COMMIT on E2's admission thread: return at once (the supervisor starts the container) and end a failed start yourself (stop, confirm, release, requeue). A raise only logs after_commit_failed and leaves the job allocated (D-47, D-72); every network call in a hook needs its own timeout.
